# M0 角色与 maker-checker 基线

| 能力 | Maker | Checker/批准人 | 强制限制 |
|---|---|---|---|
| 制度/规则发布 | 招投标负责人 | 阻断级合规由法务 | 建议人与发布人可配置分离 |
| 文件/证据维护 | 标书专员、技术负责人 | 用途/隔离由独立角色 | 维护者不能自行解除隔离 |
| 竞对资料审核 | 数据维护者 | 法务/合规或数据责任人 | 来源、用途、期限、处理基础齐全 |
| 成本基线 | 财务编制人 | 独立财务批准人 | `created_by != approved_by` |
| 商业政策 | 被授权策略人员 | 管理层/委员会 | 阈值、权重、例外版本化 |
| Provider 配置/Key | `TENANT_AI_ADMIN` | 隐私/数据责任人批准 Policy/PIA/跨境 | Key write-only；系统管理员也不能读取 |
| 风险接受 | 方案制表人以外的授权角色 | 按风险类型配置 | maker 不得 checker |
| 审批包 | 方案/报告责任人 | 审批工作流中的独立角色 | 只审批不可变包 |
| 外部提交登记 | 提交人 | 独立核验人 | VERIFIED 需要回执、实价、文件哈希 |
| LegalHold 解除 | 法务 maker | 第二授权人 | 双人控制 |
| 批量导出 | 业务 maker | 第二授权人 | 双人控制、审计可用 |
| 系统管理 | `SYSTEM_ADMIN` | 不适用 | 默认无正文、成本、Key 明文权限 |

所有授权从服务端 `IdentityContext` 推导 `tenant_id + data_domain_id + scope`。客户端提供的 scope 字段不能覆盖身份上下文。
